Written from the ticket's "Done when" only, before the code exists.

## How the integration tests prove it

The tests look at the app the way a person does, so they accept any way of building the pop-up.

- **Tapping** is a real finger tap on the emulator, at the place the app or Android says the button is.
- **"Android is asking"** means Android's permission window is in front and shows its question, with the home screen behind it and not the camera screen. An empty window Android flashes when it won't ask doesn't count.
- **"Refuses"** taps "Don't allow" on Android's real window. The second time Android asks, that's a different button, and it's the one that makes the refusal final.
- **"Refused for good"** is Android's own record: the test only goes on once Android has marked the refusal as final. Nothing is faked with a command.
- **"The pop-up appears"** means the app is in front and shows "Cần dùng camera".
- **"The camera screen doesn't open"** is checked again three seconds after the pop-up appears, so a late opening is caught. Because tapping "Đóng" must then leave the home screen, a camera screen hidden behind the pop-up fails too.
- **"Reads"** compares each text character by character, so a dropped accent or an added word fails. Texts must be in the ticket's order, title first.
- **"With an 'Đóng' button"** means "Đóng" is the only thing that can be tapped, not counting the dimmed area around the pop-up. The ticket leaves out a button that opens Settings, so an added button fails.
- **"No Android question"** means the question is never seen, from the tap until five seconds after the pop-up appears.
- **"Same pop-up"** runs the same check of the words and the button as the first pop-up.
- **"Closes and the home screen shows"** means the app is in front, shows the three sketch 1 texts, and no longer shows the pop-up.
- **"Later allowed in Settings"** goes through the real Settings, the way a person does: refuse, read the pop-up, close it, open App info, Permissions, Camera, tap "Allow only while using the app", and press back until the app is in front. The app keeps running throughout. The test checks that Android recorded the camera as allowed.
- **"Opens with no pop-up"** means the camera screen shows, and no pop-up and no question are seen until five seconds after it does.
- **Two kinds of refusal, two runs.** Android closes the app if access is taken back, so one run can't refuse, allow and refuse again. `camera_refused_driver.dart` ends refused for good, and `camera_refused_once_driver.dart` covers one refusal on its own fresh install.

## Running the automated tests

Start the emulator with `fvm flutter emulators --launch Pixel_10`. Its language must be English, because the tests read Android's question and the Settings pages.

From `app/`, run both files. Each needs a fresh install:

```sh
export ANDROID_SERIAL=emulator-5554

adb -s "$ANDROID_SERIAL" uninstall com.nampham.lotteryscan
fvm flutter drive -d "$ANDROID_SERIAL" \
  --driver=integration_test/camera_refused_driver.dart \
  --target=integration_test/camera_app.dart

adb -s "$ANDROID_SERIAL" uninstall com.nampham.lotteryscan
fvm flutter drive -d "$ANDROID_SERIAL" \
  --driver=integration_test/camera_refused_once_driver.dart \
  --target=integration_test/camera_app.dart
```

If the app isn't installed, `adb uninstall` prints a failure. That's fine: `flutter drive` removes the app when it ends, so this is the usual case. The tests in the first file run in order and are one story, so run the whole file, not one test. Don't touch the emulator during a run.

These tests are not picked up by `fvm flutter test integration_test`, because only the Mac can answer Android's question and use Settings.

## Manual steps

Screenshots go in `docs/evidence/9/`. To take one, from the repo root: `adb -s emulator-5554 exec-out screencap -p > docs/evidence/9/<name>.png`.

### Before you start

1. Start the emulator: `fvm flutter emulators --launch Pixel_10`.
2. Make sure the app has never asked: `adb -s emulator-5554 uninstall com.nampham.lotteryscan`.
3. Install the app: from `app/`, run `fvm flutter run -d emulator-5554`, then stop it with `q`.

### Step 1: the pop-up on the home screen

1. Open **Dò Vé Số** from the app list.
2. Tap **Quét vé**.
3. On Android's question, tap **Don't allow**.
4. Take the screenshot `refused-pop-up.png`.

**Should happen:** the pop-up sits over the home screen, with the home screen still there behind it, and the camera screen doesn't open. The pop-up shows, in this order:

- The title "Cần dùng camera".
- The message "Ứng dụng cần camera để chụp vé. Bạn hãy cho phép dùng camera trong phần Cài đặt của điện thoại."
- One button, "Đóng".

Every accent is drawn correctly and nothing is cut off. There's no sketch for the pop-up, so nothing to compare it with.
