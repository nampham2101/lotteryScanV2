## How the integration tests prove it

The tests look at the app the way a person does, so they accept any way of building it: any camera add-on, any file name, any folder.

- **Tapping** is a real finger tap sent to the phone, at the place the app says the button is.
- **"Never asked"** means a fresh install. Android's own record for the app must show no answer before the test starts.
- **"Android asks"** means Android's permission window is in front and its question is about taking pictures. A second question, such as for the microphone, keeps the camera screen from opening, so the test fails.
- **"Allows it"** taps "While using the app" on Android's real window. Before that tap, while Android is asking, the home screen must be what's behind the question, not the camera screen. So the test proves that allowing is what opens the camera screen.
- **"No question"** means Android's permission window is never seen while the camera screen opens, or in the five seconds after it appears, so a late question is caught too.
- **What's on screen** comes from the app's accessibility tree, which lists only what a person can see and tap. A home screen hidden behind the camera screen isn't in it.
- **"Home screen shows"** means the app is in front and shows the three sketch 1 texts and not "Đặt vé vào khung". Leaving the app by accident fails.
- **"Round shutter" and "no added buttons":** exactly one thing on the camera screen can be tapped, and it's as wide as it is tall. Its circle shape is checked in step 2.
- **"Dark background"** reads the phone's real screen pixels in six places outside the frame: beside the text, beside the shutter and in the bottom corners. All must be dark. A camera picture that fills the whole screen fails, because sketch 2 keeps the area around the frame dark.
- **"Live camera picture"** needs two things: Android reports this app as using the camera, and the picture on screen changes. The picture only changes when the view does, so it must be moving during the run: hold the phone in the hand.
- **"Kept inside the app"** means a real image file, written after the shutter tap, in the app's private folders. Files are recognised by their content, so any name or folder there counts. The app's cache folder counts too. A photo held only in memory does not.
- **"Only the new photo"** means every image file in those private folders was written after the second shutter tap. An old copy left behind anywhere there fails, including a leftover temporary file.
- **"Nothing new in the gallery"** compares Android's picture index and all picture files in shared storage, before and after. The test also requires that a photo really was taken, so it can't pass by doing nothing.
- **"No photo is taken"** means the app's photos and the gallery are the same before and after leaving, checked three seconds later. A kept photo that gets deleted or replaced fails too.
- **Back button and back gesture** are tested separately: the back key, and a finger swipe in from the left edge. The gesture test needs the phone to use gesture navigation, and stops with a SETUP message if it doesn't.

## Running the automated tests

Connect the Pixel 7 by USB, unlocked, with USB debugging on and English as its language: the tests read Android's question. Then find its serial with `adb devices`. Don't write the serial into the repo.

From `app/`:

```sh
export ANDROID_SERIAL=<serial from adb devices>
adb uninstall com.nampham.lotteryscan
fvm flutter drive -d "$ANDROID_SERIAL" \
  --driver=integration_test/camera_driver.dart \
  --target=integration_test/camera_app.dart
```

During the run:

- **Hold the phone in the hand**, so the camera picture is moving. A phone lying still can fail the tests that need a live picture.
- **Nobody touches the screen.** The tests do all the tapping. A tap by hand can answer Android's question before the test does, and the test then fails.

If the app isn't installed, `adb uninstall` prints a failure. That's fine: `flutter drive` removes the app when it ends, so this is the usual case. The tests run in order and the first two are one story, so run the whole file, not one test.

These tests are not picked up by `fvm flutter test integration_test`, because only the Mac can answer Android's question and read the gallery.

## Manual steps

Screenshots go in `docs/evidence/8/`. To take one, from the repo root: `adb exec-out screencap -p > docs/evidence/8/<name>.png`.

### Before you start

1. Connect the Pixel 7 by USB, unlocked, with USB debugging on.
2. Find the phone's serial with `adb devices`, and set it in the terminal: `export ANDROID_SERIAL=<serial>`. Every `adb` command below then goes to the phone. Don't write the serial into the repo.
3. Make sure the app has never asked: run `adb uninstall com.nampham.lotteryscan`.
4. Install the app: from `app/`, run `fvm flutter run -d "$ANDROID_SERIAL"`, then stop it with `q`.
5. Hold the phone in the hand for the steps below, so the camera picture is moving.

### Step 1: Android asks for camera access the first time

1. Open **Dò Vé Số** from the app list.
2. Tap **Quét vé**.
3. Take the screenshot `asked-for-camera.png`.
4. Tap **While using the app**.

**Should happen:** after 2, Android shows its own window asking to allow Dò Vé Số to take pictures and record video, over the home screen. The camera screen isn't open yet. After 4, the camera screen opens, with no second question.

**Screenshot:** `asked-for-camera.png`.

### Step 2: the camera screen matches sketch 2

1. With the camera screen open, wait three seconds, then take the screenshot `camera-screen.png`.
2. Wait two seconds, then take the screenshot `camera-screen-later.png`.
3. Compare `camera-screen.png` with sketch 2 in `docs/design/screens.png`.

**Should happen:** the screen looks like sketch 2.

- A dark background.
- "Đặt vé vào khung" at the top, with every accent correct and nothing cut off.
- A dashed frame in the middle.
- A round shutter button at the bottom middle.
- The live camera picture on screen. Compared with `camera-screen.png`, the picture in `camera-screen-later.png` has moved.
- No added buttons: no back arrow, no flash, no switch-camera button.

**Screenshots:** `camera-screen.png`, `camera-screen-later.png`.

### Step 3: the kept photo is the camera's picture

1. Tap the shutter.
2. List the app's files, from the repo root: `adb shell "run-as com.nampham.lotteryscan find . -type f ! -path './code_cache/*'"`.
3. Copy the photo out, using its path from that list: `adb exec-out run-as com.nampham.lotteryscan cat <path> > docs/evidence/8/kept-photo.jpg`.
4. Open `kept-photo.jpg`.

**Should happen:** after 1, the home screen shows. The photo opens as a normal picture of what the camera was showing, upright and not blank.

**Screenshot:** none. `kept-photo.jpg` is the proof.

### Step 4: no question after reopening the app

1. Close the app: open the recent apps and swipe **Dò Vé Số** away.
2. Open **Dò Vé Số** from the app list.
3. Tap **Quét vé**.
4. Wait three seconds, then take the screenshot `reopened-camera-screen.png`.

**Should happen:** the camera screen opens straight away. Android asks nothing.

**Screenshot:** `reopened-camera-screen.png`.

### Step 5: leaving the camera screen with back

Start on the home screen. Run this before and after the step, and keep both lists: `adb shell "run-as com.nampham.lotteryscan find . -type f ! -path './code_cache/*' -exec ls -l {} +"`.

1. Tap **Quét vé**, and wait for the camera screen.
2. Use the back button: `adb shell input keyevent KEYCODE_BACK`. It sends what a back button sends, so it works when the phone shows no back button on screen.
3. Wait three seconds, then take the screenshot `back-button-home.png`.
4. Tap **Quét vé**, and wait for the camera screen.
5. Read the screen's size: `adb shell wm size`.
6. Use the back gesture, a swipe in from the left edge, halfway down the screen: `adb shell input swipe 0 <half the height> <60% of the width> <half the height> 300`.
7. Wait three seconds, then take the screenshot `back-gesture-home.png`.

**Should happen:** after 2 and after 6, the app's home screen shows, not the phone's own home screen. No photo was taken: the two file lists are the same.

**Screenshots:** `back-button-home.png`, `back-gesture-home.png`.
